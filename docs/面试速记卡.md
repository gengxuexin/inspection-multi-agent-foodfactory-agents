# 面试速记卡（打印这一页就够）

> 项目：**巡检整改多Agent闭环系统**（条款映射 / 风险分级 / 证据验证）｜ 核心开发  
> 一句话：**LLM做抽取检索核验，规则做分级闸门，人保留A级确认和现场复核权**

---

## 痛点 → 方案

| 痛点              | Agent | 关键设计                                               |
| --------------- | ----- | -------------------------------------------------- |
| 跟HACCP条款对不上、查表慢 | 条款映射  | 元数据硬过滤→向量+BM25→RRF→rerank；置信度三档，**低置信度不硬猜**        |
| 人工分级易错          | 风险分级  | 20条规则并行取最高；**LLM不能单独定A级**；证据不足不低于B                 |
| 表上假改            | 证据验证  | 五道闸门：清单/元数据防旧图/哈希+pHash防复用/VLM语义/交叉校验；**打回不重置倒计时** |

## 三条硬闸门（写在代码里，不是文档里）

1. 低置信度条款映射 → **不得自动定级**，必须人工选
2. A级 / CCP → **不得仅凭照片关闭**，必须人工现场复核
3. 证据打回 → **不重置倒计时**，无效整改次数单独累计

## 架构一句话

**Orchestrator + 共享状态 + 条件路由 + 硬闸门 + HITL**。  
Agent 之间不直接对话，只通过Pydantic约束后的共享状态读写。  
`ALLOWED_TRANSITIONS` 显式声明合法转换，非法转换直接抛错。  
**闸门写在编排器不在Agent里**——Agent自己说"我判定完了"也没用。

## 阈值（网格搜索选的，16组里挑）

- 条款映射：high=0.70 / mid=0.45（错误预填率不变，预填率 37%→52%）
- pHash：≥0.95打回 / 0.85–0.95**存疑** / <0.85通过
- VLM：mismatch且conf≥0.8才打回，其余存疑转人工
- 复查比例：A 100% / B 40% / C 15%（不预先通知现场）
- 复发窗口：30天，粒度=区域+工序+条款

## 三个"为什么"（必被问）

**为什么规则表不用微调模型？** 错误代价不对称 + 法规会变 + 质量部要能逐条评审。

**为什么置信度不用单一向量分？** 单分数区分不了"检索偏了"（危险，要拦）和"条款库缺项"（该转人工补库）。

**为什么打回不重置倒计时？** 否则整改人最优策略是先随便交点什么被打回，倒计时一重置再拖几天。前面三条规则检测假证据，第四条惩罚拖延。

## 绝不能说

- ❌ "已上线，工厂在用" → ✅ "可运行工程原型，链路跑通，没做真实部署"
- ❌ "分级准确率100%" → ✅ "22条同源样本验证逻辑，真实泛化要独立标注复核"
- ❌ "用了FAISS/ChromaDB" → ✅ "自实现hashing投影为了离线可跑，换ChromaDB只需覆盖一个方法"
- ❌ "省了50%人工" → ✅ "没有工厂对照数据，指标采集实现了但没测过实际降幅"

## 主动加分的诚实表述

- "最大的收获是**约束设计**——食品安全场景里Agent互相说服的代价是整批货放行"
- "评测踩过坑：样本和规则同源写指标漂亮得不像话，所以文档里标注了每个数字的适用范围"
- "pHash最初用单阈值0.95，把真实整改也打回了一批，因为同一处积水前后背景太像；中间档改存疑后误杀就下来了"

## 最后一句（收尾用）

> 核心不是让AI替人品控，而是让**查表、分级、验证据**这三件耗人又容易出错的事被系统接住，**决策权还在人手里**。
