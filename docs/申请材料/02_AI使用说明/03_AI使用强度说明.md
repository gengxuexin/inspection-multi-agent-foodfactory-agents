## 四、换算成可理解的强度描述

如果申请方需要一个直观说法：

> **最近 10 个工作日，累计消耗约 10 亿 token 的上下文处理量，
> 模型实际生成 131 万 token，调用工具 2,909 次，日均 291 次工具调用，
> 峰值单日 812 次（相当于一天内完成数百次文件读写与测试执行）。**

按"一次 AI 协作回合约消耗 2 万 token 上下文"估算，
相当于 **约 2.5 万次模型交互**——大部分是长上下文的连续编码会话，
而不是零散的问答。

## 六、诚实说明

1. **工具调用次数不等于"AI 干了多少活"。** 一次 Bash 调用可能是一条测试命令，
   也可能是一次复杂的调试。真实工作量还要看产出物规模——两个项目合计
   **18,652 行 Python**、**105 个单元测试**、**多份设计文档**。
2. **输入 token 里 97.8% 是缓存命中**，说明大量消耗来自长上下文连续会话，
   而非反复重发相同内容。这是**上下文管理效率高**的体现，但也意味着单日 token 数
   受"会话是否连续"影响大，日与日之间可比性有限。
3. **不同模型/工具的 token 计量口径不同**，此处的绝对值不可与其他候选人横向比较，
   建议作为**趋势和投入度的自证**使用，不作为效率排名依据。
4. **未包含**在本地 IDE 插件（Cursor 等）里的用量统计，那部分在客户端本地数据库中。

## 七、复现脚本

```bash
# 在任意位置运行，会遍历全部 WorkBuddy 会话
python - << 'PY'
import json, glob, datetime
from collections import defaultdict

byday = defaultdict(lambda: [0, 0, 0])   # 输入, 输出, 工具调用
total = [0, 0, 0]

for f in glob.glob('C:/Users/Lenovo/.workbuddy/projects/*/**/*.jsonl', recursive=True):
    if '.file-rollback' in f:
        continue
    for line in open(f, encoding='utf-8', errors='ignore'):
        try:
            d = json.loads(line)
        except Exception:
            continue
        ts = d.get('timestamp')
        if not ts:
            continue
        day = datetime.datetime.fromtimestamp(ts/1000).strftime('%Y-%m-%d')
        m = d.get('message') or {}
        u = m.get('usage') or {}
        i = u.get('input_tokens', 0) or 0
        o = u.get('output_tokens', 0) or 0
        byday[day][0] += i
        byday[day][1] += o
        total[0] += i
        total[1] += o
        if d.get('type') == 'function_call':
            byday[day][2] += 1
            total[2] += 1

for day in sorted(byday):
    i, o, c = byday[day]
    print(f'{day}  输入 {i/1e6:6.1f}M  输出 {o/1e3:7.1f}K  工具调用 {c}')
print(f'\n合计 输入 {total[0]/1e6:.1f}M  输出 {total[1]/1e3:.0f}K  工具调用 {total[2]}')
PY
```

## 八、面试可能追问

**Q：10 亿 token 是不是太夸张了？**
> 总上下文处理量约 10 亿，但其中 495M 是缓存命中——**实际新处理的输入约 11M，
> 模型输出 131 万 token**。缓存命中意味着同一份长上下文被复用，
> 这是 Agent 连续编码会话的正常特征。真正反映"我写了多少东西"的指标是
> 工具调用分布（Bash 占 52%）和产出规模（18,652 行代码、105 个测试）。

**Q：这些 token 花在什么上了？**
> 主要是长上下文连续编码——读文件、改文件、跑测试、看报错、改代码、再跑测试。
> 单看 Bash 占一半就能看出来，这个工作流的重心在**验证**而不是生成。

**Q：你觉得自己 AI 使用水平如何？**
> 我认为水平高低不在 token 多少，而在**能不能判断 AI 的产出对不对**。
> 举个具体例子：Agent 生成的代码第一次跑就"看起来全绿"，
> 但我核对发现所有问题单都停在"待整改"——状态机漏了一条边而异常被静默吞掉。
> 这种问题只有理解业务和代码逻辑的人才能发现。所以我给自己定的标准是：
> **每段代码我都要能逐行解释，每个指标我都要知道它的适用边界。**
