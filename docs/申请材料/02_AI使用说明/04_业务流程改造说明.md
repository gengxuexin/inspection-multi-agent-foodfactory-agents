## 一、改造前的业务流程（问题现场）

食品工厂的巡检整改流程原本是这样的：

```
巡检员发现问题
   ↓ 手写记录（口述、拍照、写在本子上）
   ↓ 交班组长
班组长翻 SSOP/HACCP 手册查条款        ① 查表：平均 20-40 分钟/条
   ↓ 凭经验定风险等级 A/B/C            ② 分级：靠人拍脑袋，不同班组长标准不一
   ↓ 口头交代整改要求
   ↓ 责任人口头答应"我改好了"
整改人拍照提交（可能是上次的照片）      ③ 假改：口头答应、表上假改
   ↓
班组长看一眼照片 → 签字关闭
   ↓
真改了吗？没人知道                    ④ 假闭环：纸面闭环
```

### 四个可量化的痛点

| # | 痛点 | 具体表现 | 后果 |
|---|---|---|---|
| ① | **查表慢** | 巡检员口语化描述 vs 条款书面语，每条查 20-40 分钟 | 巡检员拖延录入，问题积压 |
| ② | **分级不一致** | A/B/C 靠经验，不同班组长判断不同 | **A 级漏判 = 整批货放行**，代价最高 |
| ③ | **假改难识别** | 照片可以复用、可以拍别处、可以是旧图 | 安全隐患流入下道工序 |
| ④ | **超时无人催** | 整改时限靠人记、靠人催 | 问题拖到下一轮巡检才被发现 |

**这些痛点的共同特征：全是"重复性判断 + 需要留痕"的活儿，而不是需要专家经验的核心决策。**
这正是 AI 系统该接的部分。

## 二、改造后的业务流程

```
巡检员语音/拍照/文字录入
   ↓
[Agent 1 巡检录入]  自动结构化：区域/工序/现象/批次/设备
   ↓ 低置信字段标黄，巡检员确认
   ↓
[Agent 2 条款映射]  自动检索 → Top-3 条款 + 原文 + 置信度
   ├─ 高置信 → 预填（巡检员可改）
   ├─ 中置信 → 强制人工选（展示 Top-3）        ← 闸门①
   └─ 低置信 → 显式弃答 + 提示"未匹配到可靠条款"
   ↓
[Agent 3 风险分级]  20 条规则并行 → 取最高等级 + 全部理由
   ├─ 规则命中 → 输出等级/依据/理由
   └─ 规则未命中 → LLM 给建议，但不能单独定 A 级   ← 闸门②
   ↓ A级/CCP/证据不足/规则冲突 → 强制人工确认
   ↓
[Agent 4 整改派单]  自动生成：责任人 + 时限 + 必交证据清单
   ↓ （证据类型由问题类型+等级决定，不能自选删除）
[Agent 5 跟踪升级]  启动倒计时，超时按级自动上推
   ↓ 打回不重置倒计时，无效整改次数累计          ← 闸门③
   ↓
[Agent 6 证据验证]  五道闸门
   ① 清单完整性 → 缺项打回
   ② 元数据     → 拍摄时间早于派单 = 旧图，打回
   ③ 复用检测   → 哈希一致 / pHash≥0.95，打回
   ④ 语义核验   → VLM 明确不符才打回，存疑转人工
   ⑤ 交叉校验   → 与 MES/设备日志矛盾，存疑转人工
   ├─ 打回 → 无效整改+1，倒计时继续，通知责任人
   ├─ 存疑 → 人工复核（B级远程 / A级现场）
   └─ 通过 → 进复查抽验
   ↓
[Agent 7 复查抽验]  A 100% / B 40% / C 15%，不预先通知现场
   ├─ 通过 → 授权人签字关闭
   ├─ 不通过 → 等同无效整改，打回重开
   └─ 30 天内同区域同工序同条款复发 → 自动升级 CAPA
```

### 关键改造点对照

| 原流程环节 | 改造后 | 改变的性质 |
|---|---|---|
| 手写记录 | Agent 自动结构化，低置信字段标黄 | **录入提效**，人不做录入 |
| 班组长翻手册查条款 | RAG 自动召回 Top-3 + 原文 + 理由 | **查表自动化**，人不做检索 |
| 凭经验定级 | 20 条规则并行评估 + 理由留痕 | **判定标准化**，A 级漏判有兜底 |
| 口头交代整改要求 | 自动生成含证据清单的整改单 | **要求显性化**，不能口头带过 |
| 靠人记时限、靠人催 | 三级响应时钟，超时自动上推 | **催办自动化**，不依赖人记性 |
| 看一眼照片就签字 | 五道闸门 + A级强制现场复核 | **验收有依据**，假改有拦截 |
| 无追溯 | 全链路审计日志（只追加） | **过程可追溯** |

## 三、改造后的差别（对比表）

### 3.1 职责重新分配

| 工作 | 改造前 | 改造后 | 变化 |
|---|---|---|---|
| 记录问题 | 人工手写 | AI 结构化 + 人确认异常字段 | **人做复核而非录入** |
| 查条款 | 人工翻手册 | AI 检索 Top-3 | **人做选择而非查找** |
| 定风险等级 | 人工凭经验 | 规则判定 + 人工确认 A 级 | **人做决策而非判断** |
| 派单 | 口头交代 | 系统生成结构化整改单 | **人不再需要重复交代** |
| 催办 | 人工记着谁没改 | 超时自动上推 | **催办不再依赖人** |
| 验证据 | 看一眼照片 | 五道机器校验 + 人工现场复核 | **机器初筛，人做终审** |
| 追溯 | 纸面单据 | 只追加审计日志 | **可回放全链路** |

### 3.2 三个最本质的变化

**① 判定从"人凭记忆"变成"规则可复核"**
> 原来 A/B/C 是班组长说了算，不同人标准不一样，而且没人能说清为什么是 A 级。
> 现在每条判定都对应具体规则 ID 和理由模板，质量部能逐条评审规则表对不对，
> 也能逐条追溯某个问题为什么被定为 A 级。

**② 假整改从"靠人眼发现"变成"机器主动拦截"**
> 原来交照片就签字，人只能看出明显不对。
> 现在系统主动查四件事：证据齐不齐、是不是旧图、是不是历史复用、内容对不对得上。
> 其中"旧图"这一项是靠拍摄时间对比派单时间解决的——**这是人工签字时根本不会去核的**。

**③ 超时从"靠人催"变成"系统上推"**
> 原来整改拖着没人管。
> 现在倒计时由系统维护，超时按 A/B/C 分级自动上推到班组长→车间主任→厂长。
> **特别地，打回不重置倒计时**——否则整改人最优策略是先交点东西被打回，
> 倒计时一重置再拖几天，对 B 级（3 个工作日）能让问题无限期悬置。

### 4.2 改造前后对比（业务视角）

| 维度 | 改造前 | 改造后 | 变化 |
|---|---|---|---|
| 查条款耗时 | 20-40 分钟/条 | 秒级检索 + Top-3 供选 | **量级下降**（未做真实计时，见下） |
| 分级一致性 | 依赖个人经验 | 规则统一 + 全部理由留痕 | **可复核、可追溯** |
| A 级漏判 | 无人兜底 | 规则强制命中 + CCP 强制人工 | **有兜底机制** |
| 假改识别 | 人眼看照片 | 4 类机器校验主动拦截 | **从被动到主动** |
| 超时处理 | 人工催办 | 系统自动上推 | **不依赖人的记性** |
| 追溯能力 | 纸面单据，过程难还原 | 只追加审计日志，全链路可重放 | **可审计** |
| 人工投入方向 | 录入 + 查找 + 判断 + 催办 | 只做**选择、确认、现场复核** | **从事务性转向决策性** |

### 4.3 必须说明的（不能夸大）

> **⚠️ 上表中的"改造后"结果全部来自原型环境的构造验证，不是真实工厂的生产数据。**

| 项 | 说明 |
|---|---|
| **耗时数据** | "20-40 分钟/条"是**设计稿给出的业务访谈假设**，不是我实测的。系统侧我没有做真实计时，因为没有真实巡检员使用。 |
| **误杀率 0%** | 120 条样本是**构造**的（四类各 30 条，构造方式明确所以逻辑正确）。真实照片库上一定更高，目标控制在 5% 以内。 |
| **分级 100%** | 22 条样本且**规则与样本同源**，只验证逻辑正确性。真实场景需质量专家独立标注 100-200 条复核。 |
| **真实部署** | **未在工厂上线**，未接入真实 MES、未接企业真实条款库。 |
| **真实 LLM/VLM** | 默认跑 mock，真实模型接入后行为会有差异。 |
| **人力节省** | **没有实测数据，不编这个数。** 我实现了指标采集接口（自动流转率、人工介入率、待办积压、平均闭环时长），但没有真实数据源。 |

### 4.4 我认为这个流程改造真正的价值

不是"快了多少"，而是这三件事：

> **① 判定标准从个人经验变成了可复核的规则**
> 食品安全判定必须能追溯到依据。以前是"班长说的"，现在是"规则 A03 + 条款 CCP-01 原文"。
>
> **② 假整改有了技术拦截手段**
> "旧图复用""拍别处"这两类，人工签字时基本发现不了。系统能查。
>
> **③ 系统替人做的是"耗人且容易错"的活，不是"需要判断"的活**
> 查表、分级、验证据是事务性的；A级确认和现场复核是决策性的。
> **这套改造让人的时间从查表挪到了判断上，而不是把人替掉。**
> 这是我做这个系统时坚持的核心原则——也是我在面试里最想讲清楚的一点。

## 五、配套的消防项目改造（第二个佐证）

同一套方法论在另一个场景的复用：

| 维度 | 改造前 | 改造后 |
|---|---|---|
| 法规查询 | 人工翻法规原文 | RAG 混合检索 + 文档级权限过滤 |
| 多模态案件材料 | 人工看图看视频听录音 | 自动分类路由 → 分模态并行处理 → 综合研判 |
| 法律文书 | 人工从零起草 | 模板驱动 + LLM 字段抽取，三级字段分流（事实/法律/待补充） |
| 人工审批 | 只记"通过/驳回" | **改动检测 Agent**：自动对比改动前后，产出可归档报告 |
| 视觉隐患 | 人工巡检 | YOLO 检测 + OCR + 多模态大模型综合判断 |

**改动检测这一项特别值得说**，它解决的四个盲区很典型：
- 模板缺陷不闭环（人工每次改同样的地方，没人统计）
- LLM 抽取错误无法定位（分不清"模型抽错"还是"人理解不同"——两种问题解法完全相反）
- 风险改动不可见（人工把"五万元"改成"五十万元"，系统无感知）
- 幻觉无法追溯（终稿出现知识库里没有的条款，不能自动报警）

## 六、面试时怎么讲这段（90 秒版）

> "我改造的是食品工厂的巡检整改流程。
>
> **改造前**是这样的：巡检员手写记录，班组长翻 SSOP 手册查条款——一条要二十分钟到四十分钟，
> 而且不同班组长定级标准不一样。整改环节最麻烦，口头答应、表上写改了但其实没改，
> 有的甚至交上次的照片。超时了也没人知道。
>
> **改造后**我把它变成一条系统化的闭环：条款映射 Agent 自动检索 Top-3 给候选，
> 风险分级 Agent 用 20 条规则判定并给出依据，证据验证 Agent 做五道闸门——
> 清单完整性、元数据防旧图、哈希加感知哈希防复用、VLM 语义核验、交叉校验。
>
> **差别最明显的是三点**：
> 第一，判定从'班长凭经验'变成'规则可复核'，每条判定都能追溯到规则 ID 和条款原文；
> 第二，假改从'人眼看照片'变成'机器主动查四类问题'——特别是拍摄时间对比派单时间，
> 这是人工签字时根本不会去核的；
> 第三，超时从'靠人催'变成'系统按级自动上推'。
>
> **我特意加了一条反直觉的约束：打回不重置倒计时。**
> 因为如果打回后倒计时重置，整改人的最优策略就变成'先随便交点什么被打回，
> 倒计时一重置，再拖几天'——对 B 级 3 个工作日的问题能让它无限期悬置。
>
> 但我必须说清楚：**这些结果都来自原型的构造验证，不是真实工厂的生产数据。**
> 我实现了指标采集接口，但还没接真实数据源。真正的价值我认为不是快了多少，
> 而是让人的时间从事务性的查表核验，挪到了决策性的确认和现场复核上。"

## 七、如果被问"改造后到底省了多少人力"

> **这个数我没有，我不编。**
>
> 我能提供三样东西：
> 第一，系统侧的指标采集接口已经实现——自动流转率、人工介入率、待人工任务积压量、
> 平均闭环时长、非法状态转换次数，能直接从运行数据算出来；
> 第二，改造前后的流程对照和机制差异是明确的，比如原来每条查表 20-40 分钟是业务访谈给出的假设，
> 现在检索是秒级的，但**巡检员从录入到确认的总耗时我没做过真实计时**；
> 第三，最该盯的指标其实不是人力节省，而是**无效整改次数**——
> 这是"表上假改"这个痛点的直接度量，改造前它基本是看不见的，
> 改造后系统会单独累计并进部门统计。
>
> 如果贵司有真实数据源，我可以在实施阶段直接测这个口径。
