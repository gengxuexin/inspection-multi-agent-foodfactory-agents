| ❌ 不能说 | ✅ 要说 |
|---|---|
| "已在工厂上线" | "可运行的工程原型，完整链路跑通，未做真实部署" |

| "VLM 能准确识别照片" | "VLM 是 mock 启发式实现（按文件名标注模拟判定），真实模型接入后需在真实照片库重测误判率" |
| "用了 FAISS / ChromaDB" | "向量检索是自实现的可复现 hashing 投影（保证离线可跑），BM25 与 rerank 亦为自实现轻量版；替换 ChromaDB 只需覆盖一个方法" |
| "上线后省了 50% 人力" | "没有真实工厂对照数据，不编这个数；我实现了指标采集接口但未测过实际降幅" |
| "误杀率 0%" | "120条**构造**样本（构造方式明确所以逻辑正确），真实场景误杀率一定更高，目标控制在5%以内" |
| "模型学到了专家经验" | "规则表是专家规则，LLM 只在规则未命中时给建议，全程不训练模型" |

### 关于 AI 署名的说明

两个项目 git 历史里都保留了 `Co-Authored-By` 标注。这是**主动披露而非隐藏**：
目前主流开源社区（如 Linux 内核、Python 等）都接受 AI 辅助提交的署名惯例。
在申请语境下，主动披露 + 说清"人做了什么决策"，比让人以为全手写更安全。

**面试时主动说这句：**
> "项目是我用 AI 辅助开发的，git 历史里能看到 AI 协作署名。我没有隐藏这点。
> 我负责的是需求拆解、架构决策、硬约束设计和最终验证——比如'打回不重置倒计时'
> 这条业务规则，是我在设计时推导出来的，AI 负责把它翻译成代码和测试。"
